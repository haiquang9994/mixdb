# Translations

Every user-visible string goes through `t()`. No literal English in JSX.

```tsx
const { t } = useTranslation();
<button title={t("app.closeTab")}>{t("common.save")}</button>
```

## Rules

- `src/i18n/en.ts` is the source of truth for the key set: `TranslationKey` is derived from it as
  dotted paths, so a key missing from `en.ts` is a type error at the call site, and a key missing
  from `vi.ts` is a type error in `vi.ts` itself. Add to **both** files.
- Group keys by area: `common.*` for words reused everywhere, then one namespace per feature
  (`app.*`, `connection.*`, `mysql.*`, `sqlTable.*`, `redis.*`, …).
- Interpolation is `{{name}}`, filled by the second argument:
  `t("connection.connectedStatus", { id })`. An unmatched placeholder is left as-is.
- An unknown key resolves to the key string itself rather than throwing — so a missing translation
  shows up as visible junk in the UI, not a crash.

## Errors from the backend

A rejected `invoke` carries an `AppError` — `{ code, params, cause? }` — not a message. Never
render it directly; put it through `errorMessage` from [src/errors.ts](../../src/errors.ts):

```tsx
try { await mysqlDropTable(id, db, table); }
catch (e) { onError(errorMessage(t, e)); }
```

`code` is a key under `error.*`, so adding a backend error means adding its key to `en.ts` and
`vi.ts` like any other string. What a driver said travels as the `message` parameter and stays in
the server's own words.
- Non-ASCII characters are written as escapes in the dictionaries (`"✓ Tunnel OK"`).

## Language selection

`I18nProvider` wraps the app in `main.tsx`. The choice persists in `localStorage` under
`mixdb-lang`, defaulting to `en`. `useTranslation()` throws outside the provider.
