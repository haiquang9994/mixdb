# Review 2026-08-27

**Scope:** the whole repository at `24be307` (v0.0.18, 214 commits on `master`) — `src/`,
`src-tauri/src/`, the scripts, the workflows and the `.agent/` notes.
**Method:** four independent read-throughs (Rust backend; shell/core/components; the three
modules; hygiene and docs), each finding re-read at the cited line before it was kept. The
suspicious pure-logic cases were executed. Baseline on this machine: `npm run build` clean
(one 1.8 MB chunk warning), `npm test` 51 files / 758 tests green, `cargo check` and
`cargo clippy` clean, `cargo test` 122 passed / 4 ignored.

**Overall:** the project is in good shape — the module boundary really holds, identifiers and
values never reach SQL unquoted, credentials never reach a command line, and the async guards
in the newer code (schema cache, tunnel banner, query draft) are the kind most apps lack. The
open problems are concentrated in three places: connection and session **lifecycle at the
edges** (cancel during connect, shell exits on its own, script state left on a pooled
connection), **PostgreSQL-specific** gaps in the SQL guard and splitter, and **duplication** that
has passed the "third copy" threshold the notes themselves set. There is no CI that runs any
of the tests.

**Read these first:** R1 (CSP breaks the 0.0.18 headline feature in the packaged build), R2
(`EXPLAIN ANALYZE` bypasses the read-only guard), R3 (script leaves a transaction on a pooled
connection), R4 (SSH session leaks when the shell exits), R6 (connect cannot be cancelled).

## Bugs

- [x] **R1** `src/modules/rest/components/HtmlPreview/HtmlPreview.tsx:59` (`sandbox`, `srcDoc`)
  vs `src-tauri/tauri.conf.json:25` (`csp`). An `about:srcdoc` document inherits the embedder's
  CSP. Production CSP is `script-src 'self'` with no `'unsafe-inline'` and `img-src 'self' data:`,
  so in the packaged app the page's inline scripts and its external images/stylesheets are
  blocked no matter which switch is on; `devCsp` has `'unsafe-inline'`, which is why `dev:app`
  shows it working. Commit `6f55248` did not touch the CSP. *Verify on a packaged build before
  fixing; the fix is a `<meta http-equiv="Content-Security-Policy">` injected into the srcdoc or a
  looser CSP scoped to the frame, not `'unsafe-inline'` for the app.* Also `:36` only injects
  `<base>` when the document has a `<head>`.
  **Fixed.** Confirmed on a packaged build over CDP: the app CSP arrives as `script-src 'self'` plus
  Tauri's two hashes, and the frame's inline script is blocked. The `<meta>` half of the suggestion
  above does **not** work — CSP policies intersect, so a policy delivered inside the frame only ever
  tightens, and `data:`/`blob:` frames inherit the same way. The one document that carries a policy
  of its own is a served one, so `src-tauri/src/modules/rest/preview.rs` registers a `mixdb-preview`
  scheme and answers with the response body under a CSP the pane's two switches pick; `frame-src`
  names that scheme and nothing else. `img-src` gained `blob:` in the same edit — the Preview tab's
  image body is a blob URL and was blocked in the packaged build for the same reason.
- [x] **R2** `src/modules/db/sql/guard.ts:263-265` (`READ_VERBS`), `:287-326`
  (`writingStatements`), `:148` (`unguardedWrites`). `EXPLAIN` is a read verb unconditionally, but
  `EXPLAIN ANALYZE <stmt>` executes the statement on PostgreSQL (always) and MySQL ≥ 8.0.18.
  Executed: `writingStatements("EXPLAIN ANALYZE DELETE FROM users")` → `[]` on both dialects. On a
  read-only connection this deletes the table without a prompt.
  **Fixed.** Both gates now judge an `EXPLAIN ANALYZE` by the statement it is given: `judged()` reads
  past `EXPLAIN` and its options and hands the inner statement to `writingStatements` and to
  `unguardedWrites`, so `EXPLAIN ANALYZE DELETE FROM users` is refused as a `DELETE` and asked about
  as one. Whether it analyses is decided over the statement's own tokens rather than the top-level
  ones, because PostgreSQL's `EXPLAIN (ANALYZE, VERBOSE) ...` hides the word inside brackets that
  `topLevelWords` drops; `ANALYZE`/`ANALYSE` are reserved in both dialects, so an unquoted one can
  only be the option. A plain `EXPLAIN DELETE` still passes — it plans and runs nothing. Cases in
  `guard.test.ts` for both dialects, both spellings and the CTE behind one.
- [x] **R3** `src-tauri/src/modules/db/drivers/mysql_script.rs:325-345` (`run`, the `USE` at
  `:341`), `postgres_script.rs:339-427` (`run`), `mysql.rs:78-85` (`query`), `mysql_script.rs:257-301`
  (`validate`: `SET @mixdb_check`, `PREPARE`). A script runs on `pool.acquire()` and the connection
  goes back with whatever the script left: an open `BEGIN`, a `USE other_db`, `SET autocommit=0`,
  `LOCK TABLES`, temp tables. sqlx only pings on return. `BEGIN; SELECT 1/0;` on PostgreSQL leaves
  an aborted transaction that the next `list_tables`/`table_data` on that connection fails with
  (`25P02`); an uncommitted `UPDATE` on MySQL holds row locks on an idle connection until a later
  `pool.begin()` implicitly commits it. Run scripts on a detached connection, or roll back /
  close when `in_transaction()` after the script.
  **Fixed.** Both `run`s now call `PoolConnection::close_on_drop()` on the connection they acquire, so
  the script's session is closed when the run ends instead of going back to the pool. On drop rather
  than at the end, which covers the error paths and the run being dropped because the tab closed; the
  pool keeps the permit meanwhile, so this never opens a sixth connection. Neither server has a
  statement that would do instead — MySQL has no session reset at all, and PostgreSQL's `DISCARD ALL`
  needs a connection that is not mid-transaction, which is the case that has gone wrong. The cost is
  one handshake per Run.
  Reproduced against the test servers with a `max_connections(1)` pool, then re-run with the fix
  removed: PostgreSQL gave `25P02 current transaction is aborted` on the query after
  `BEGIN; SELECT 1/0;`, MySQL gave back `42` for `SELECT @mixdb_r3` after a script had set it. Both
  pass with the fix. The checks were temporary — they need a live server, so nothing was committed.
  `validate` still keeps its pooled connection on purpose: it fires on a debounce while someone
  types, and what it leaves (the `USE`, `@mixdb_check`) is bounded and read by nothing — every other
  query names its database in full or binds it to `information_schema`. Noted in its doc comment.
  `mysql.rs:78-85` needed no change: `query` issues its own `USE`, and it has no callers today.
- [x] **R4** `src-tauri/src/modules/terminal/remote.rs:36-63` (read task), `:67-92` (write task
  holding the SSH `Handle`), `local.rs:293-328`, `state.rs:19-25` (`Session::drop`),
  `commands.rs:96` (the only `sessions.remove`). When the shell exits on its own the read task
  ends but nobody cancels `kill`, so the write task — and the SSH connection with its 15 s
  keepalive — lives until `Session` is dropped; and `TerminalView.tsx:208` skips `closeSession`
  once `ended`, so the `Session` stays in the map for the life of the app. Type `exit` in an SSH
  tab: TCP session and keepalive run forever; local shells leave two blocked threads and a task
  per closed tab. Cancel `kill` when the read task ends and remove the entry on `Exit`.
  **Fixed.** Removing the entry on `Exit` turned out to cover both halves: `Session::drop` already
  cancels `kill` *and* releases the two senders, and it is releasing the senders — not the token —
  that wakes the local write and resize threads, which block on `blocking_recv()` and would not have
  noticed a cancelled token. So the sink now calls `TerminalState::forget(id)` when it emits `Exit`,
  and that one call ends the SSH write task (closing the channel, the `client::Handle` and the
  keepalive with it), the local write/resize threads and the killer task.
  Two details: the removed `Session` is dropped outside the lock, and `terminal_open` re-checks an
  `ended` flag under the same lock right after inserting — a shell that dies instantly emits `Exit`
  before `spawn` returns, and without the re-check that dead session would be inserted after the
  removal had already run and nothing would ever take it out again.
  `output_sink` came out of `terminal_open` so a test can drive the real sink: building a mock
  `AppHandle` fails on this machine (`tauri`'s `test` feature makes the test binary die with
  `STATUS_ENTRYPOINT_NOT_FOUND` before any test runs), and the only line left outside the test is
  the one that pulls `TerminalState` off the handle. `commands.rs` test
  `a_session_that_ends_by_itself_leaves_the_map` spawns `exit 3` and waits for the map to empty; it
  fails as expected with the `forget()` call removed.
  `TerminalView.tsx:208` needed no change: skipping `closeSession` once `ended` is now correct, and
  the doc comment on `terminal_close` says so.
- [x] **R5** `src/modules/terminal/components/TerminalView/TerminalView.tsx:181-215` (open
  effect + cleanup) vs `src-tauri/src/modules/terminal/commands.rs:26-55` (`terminal_open`
  inserts only after `spawn(...).await`). Close the tab during the SSH handshake: cleanup calls

  `.test.tsx` — and adding one for a single effect race is more than this is worth. Checked by
  reading, with `tsc` and the 775 tests green.
